# 小手机 · Mini Phone

> 给 SillyTavern 装一部真的能用的手机。

角色在正文里说的每句话，手机上都能收到；手机里有自己的消息列表、朋友圈、联系人，台词可以用角色自己的声音念出来。整套东西跑在你的浏览器里，不额外装服务，不改酒馆源码。

**当前版本 0.17.1** · [更新记录](../../commits/main) · [语音设计](docs/VOICE-DESIGN.md) · [发布流程](docs/UPDATING.md)

---

## 它解决什么

酒馆的正文是一长条文字，所有信息平铺在同一层里：

- 角色说了什么，要自己在段落里找
- 想听角色的声音，得另外开一个 TTS 工具
- 角色「私下发消息」这种情节，只能靠旁白描述
- 好感度、欠债、约定好的事，散落在几百楼里

小手机把这些拆出去，做成一个**独立于正文的第二空间**：

```
正文                        小手机
────────────────────        ────────────────────
「晚上有空吗？」     →       消息 · 梨诺 · 20:14
（她等了很久）              「晚上有空吗？」
                                  ↑ 点一下，用她的声音念
```

正文照常推进，手机负责那些正文里塞不下的部分。

## 能做什么

### 正文这一侧

| 能力 | 说明 |
|---|---|
| **台词识别** | 从正文里拆出「谁 / 什么情绪 / 译文 / 原文」，四种写法都认（见下方） |
| **念整段** | 每层正文末尾长出 `▷ 念整段（N 句）`，一次念完这一楼 |
| **手机联动** | 正文里写 `<phone>` 块，消息、图片、转账、红包、礼物、歌曲、位置、朋友圈真的出现在手机上 |
| **格式自适应** | 模型没按格式写也能认出对话，不要求它必须吐 XML |

### 手机这一侧

六个 App，配色和用途分开：

| App | 干什么 |
|---|---|
| **消息** 💬 | 会话列表 + 联系人。点人开聊，回复流式吐字 |
| **朋友圈** 🖼️ | 角色发动态、点赞、评论；正文写 `[朋友圈]` 也会同步进来 |
| **朗读** 🎧 | 把整个聊天的台词抽成清单，一页一个角色，支持逐句跳和目录 |
| **角色** 🎭 | 音色管理。卡片网格，逐个配头像、音色、语言，可试听 |
| **我** 🙂 | 玩家自己的 persona：头像、名字、描述、统计 |
| **设置** ⚙️ | 三个二级页：常规 / 聊天模型 / 语音模型 |

### 两套接口都能在前端配

**不是写死的白名单**，是配置档案：

|  | 聊天模型 | 语音引擎 |
|---|---|---|
| 存几套 | 多套，下拉切换 | 多套，下拉切换 |
| 内置模板 | OpenAI 兼容 / DeepSeek / Gemini / 本地 | OpenAI 兼容 / Fish / MiniMax / 浏览器朗读 |
| 可改字段 | 地址、Key、模型、温度、长度、请求地址、额外请求头、额外请求体、流式开关 | 地址、Key、模型、音色、请求地址、请求头、请求体、响应格式、情绪写法、语速 |
| **中转/反代** | ✅ 只换域名，路径保留 | ✅ 同一套规则 |
| 新建 | ＋ 新建配置，从空白填 | ＋ 新建自定义引擎，从空白填 |
| 诊断 | 一键测连通（耗时 + 回复） | 一键测连通 + **查看实际请求**（URL / 头 / 体，Key 打码） |

**加一家服务商 = 加一条配置数据，不改一行代码。**

## 认哪些正文格式

同一张卡里几种写法混着用也没关系，从严格到宽松依次尝试：

| 优先级 | 写法 | 例子 |
|---|---|---|
| 1 | XML 标签 | `“译文”<tts>佩拉｜疑惑｜原文</tts>` |
| 2 | 引号 + 竖线 | `“译文”佩拉｜疑惑｜原文` |
| 3 | 名字 + 冒号 + 引号 | `**梨诺**：“台词”` ／ `梨诺：“台词”` |
| 4 | 纯引号 | `“没有标注说话人的台词”` → 归给「旁白」 |

引号认 `“”` `""` `「」` `『』` 四种。

---

## 语音怎么省钱（都自动做）

| 机制 | 作用 |
|---|---|
| **内容指纹缓存** | 同一句只付一次。指纹 = 地址 + 请求体 + 音色 + 模型 + 情绪 + 文本，任一项变了才算新的一条 |
| **跨请求去重** | 同一句正在合成时，后来的请求等结果，不重复下单 |
| **只预取一句** | 念这句时下一句已经在做，点的时候立刻响；只预一句，不做无用功 |
| **整段是显式操作** | 不会自动念，点了才花钱 |

缓存存在 IndexedDB，默认上限 200MB，按最后使用时间淘汰。

## 安装

**方式一：酒馆里装**

```
扩展 → 安装扩展 → 粘贴 https://github.com/GGGFFF-Create/mini-phone
```

**方式二：手动（能用 git pull 更新）**

```powershell
cd <SillyTavern>\public\scripts\extensions\third-party
git clone https://github.com/GGGFFF-Create/mini-phone.git
```

刷新酒馆 → 魔棒菜单 →「打开小手机」。

> 目录名必须是 `mini-phone`，和 manifest 的 `name` 一致。

## 第一次用

```
1. 设置 → 聊天模型    填地址 + Key + 模型名，点「测试这套配置」
2. 设置 → 语音模型    选引擎；想先不花钱就选「浏览器朗读」，不用 Key
3. 角色页             点卡片 → 填音色 ID → 试听
4. 正文聊一轮         每楼末尾应该长出「▷ 念整段」
5. 发条手机消息       看回复是不是逐字长出来
```

## 结构

```
manifest.json      扩展清单（version 必须和 index.js 的 VERSION 一致）
index.js           宿主层 —— 唯一 import SillyTavern 的文件
style.css          宿主侧样式（浮窗 + 正文按钮）

core/              不碰 DOM、不碰酒馆，可以直接跑测试
  protocol.js      正文解析：标记 → 按钮（三阶段）
  phone.js         <phone> 块解析
  store.js         IndexedDB（按角色卡分区）
  llm.js           聊天模型：配置档案、上下文、流式
  chat.js          会话服务
  moments.js       朋友圈服务
  tts/             语音：引擎 / 合成 / 缓存 / 播放

ui/                iframe 内部（不认识酒馆）
  phone.js         外壳：锁屏、桌面、路由、底部导航
  apps.js          App 注册表（唯一要改的地方）
  apps/{chat,moments,listen,roles,me,settings}/
```

**分层原则**：`core/` 不知道 DOM 存在，`ui/` 不知道酒馆存在，`index.js` 是唯一的粘合层。所以核心逻辑能在 node 里直接测。

## 已知限制

| 限制 | 原因 |
|---|---|
| 酒馆 1.18 的正文按钮走 DOM 注入 | `getContext()` 每次返回新对象，改 `messageFormatting` 不生效。新版酒馆有 `messageFormatter.addHook` 时优先走标准三阶段 |
| 正文按钮是「整楼一次」而不是「每句一个」 | DOM 里的文本被酒馆正则改写过，按译文定位会插错位置 |
| 某些中转不认 `stream` 参数 | 自动检测并回退到整段返回，控制台会打印一行提示 |
| 音色语言由音色本身决定 | 部分服务商（如 Fish）不看 `language` 字段，要换对应的中文音色 ID |
